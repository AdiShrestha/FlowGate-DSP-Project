## 5. Why the principal defects change the scientific conclusion

### 5.1 Point metrics and event metrics were mixed

For strict point evaluation, TP must be `sum(label==1 and prediction==1)`, FP must be `sum(label==0 and prediction==1)`, and recall is TP divided by the number of original positive points. If a task permits a tolerance interval, define a separately expanded label task consistently or use a declared event-matching rule. Do not take TP from an expanded window, denominator from the original mask, and then clip recall to one. Those three steps create a metric that cannot be interpreted as ordinary point recall.

The retained counterexample is especially diagnostic: the only label is at index 500, and the only alert is at 499. The legacy routine reports precision=1, recall=1, F1=1, FP rate=0 and its custom ROC routine reports AUROC=1, although the strict point task has zero TP and one FP. The legacy detected-latency value is missing because its latency search does not include the early alert. The contradiction is recorded in `targeted_probes.json`. An early alert can be meaningful in a forecasting task, but that would require a distinct prospectively defined forecast target; it cannot silently become successful anomaly detection.

The new `point_metrics` uses all score thresholds/tie groups, consistent original labels, exact ROC integration, and non-interpolated AP. It accepts ranking scores without inventing calibrated probabilities. `event_metrics` keeps one-to-one alert/event matching, misses, unmatched alerts, detected-only latency explicitly named, and right-censored windows. It currently implements a declared greedy chronological matching rule; overlapping events need a dataset-specific review before that rule becomes the primary protocol. The code does not turn detected-only mean latency into an unconditional guarantee.

Per-type evaluation also needs correction. Other anomaly types cannot silently become ordinary negatives if the analysis claims “detection within point anomalies versus clean background.” Register whether other types are excluded, treated as negatives for a one-vs-rest discrimination task, or jointly modeled. The old code evaluated all timestamps against one type mask, so it could penalize valid alerts to other perturbations. Different choices answer different questions.

### 5.2 The modeled queue and derived capacity do not support throughput claims

A physical workload/wait recurrence needs service duration and elapsed time in consistent units. For FCFS, with arrival `a_i` and service duration `s_i`, start is `max(a_i, finish_(i-1))`, finish is start plus `s_i`, and waiting is start minus arrival. Lindley waiting time is `W_(i+1)=max(0,W_i+s_i-(a_(i+1)-a_i))`. If a fluid item-queue approximation is used instead, draining over an interval is proportional to `mu * delta_t`; it is not `service_time / delta_t`. The legacy implementation's latter term decreases when the server is faster, the opposite of the intended behavior.

Legacy tests sometimes passed because the separate condition `rho<1` already encoded a desired stability answer and the empirical slope tolerance was forgiving. A separate test file used its own different recurrence rather than calling the executed production operator. Neither establishes that the plotted queue represented a server. The new exact FCFS scheduling model has independently hand-calculated waits, idle periods, and overload sequences. Its outputs are explicitly **model outputs**, not measurements. Finite-run boundedness alone cannot prove infinite-horizon stability.

For a shedding implementation timed per original input event, let the measured total cost already include admitted/skipped events. Inverting that average yields its modeled input capacity under the timing assumptions. Dividing again by the admitted fraction double counts the skip benefit. A correct analytical decomposition must measure ingress/controller cost `c_i` on all inputs and downstream cost `c_d` on admitted inputs, giving approximately `c_i + p*c_d` before queueing and synchronization overhead, with admission probability/fraction `p`. If `c_i` dominates, reducing `p` gives little benefit. If the alleged gain comes only from fixed shedding, adaptation has not been shown to contribute.

The old arrival sweep extends from approximately ordinary trade rates to hundreds of thousands of modeled events/s. That can be a clearly declared accelerated workload study, but not a claim that those are natural input rates or observed service rates. Choose one common offered-load grid learned from pilot capacity, disclose acceleration, measure actual realized arrivals/completions, and retain backlog growth and all losses. Do not select a showcase lambda after inspecting which method wins and present it as the whole result.

### 5.3 The “150 independent / 300 anomalies / three types” description is unsupported

The multi-seed CSV has 3,150 rows: 1,050 each for `all`, `level_shift`, and `point`, and **zero `volatility_burst` rows**. The 150 trial keys use 96 distinct asset-days. Seed labels 0–49 repeat across three regimes, creating 700 duplicate `(seed,config)` rows in the all-type table. Seeds are not natural market populations. They primarily vary injection randomness, and sampling days with replacement does not produce new independent days.

The injector silently stops a type when no space remains. A 50,000-event series with requested 100 anomalies/type at seed 0 produced 100 point events and 23 shifts; no volatility bursts were added. Its exclusion zones and sequential type order create an imbalanced, order-dependent task. No amount of rewording can make that run a three-type 300-event experiment. Future deliberately artificial experiments must preserve actual event counts and demand feasibility before execution or fail, rather than silently changing the task. These would be declared simulation studies, not natural financial anomaly detection.

The default use of the first 50,000 events also provides different physical durations across asset-days and omits much of each day. Full-day regime labels are retrospective and use information beyond that prefix. They can be valid descriptive subgroup labels after evaluation, but are not an online feature or justification that the prefix represents that regime. Define temporal windows and subgroup timing prospectively.

### 5.4 Initialization, coefficient traces, and frozen pictures are different objects

The zero-state EMA impulse response is `h[n]=alpha*(1-alpha)^n`, and its zero-state unit-step response is `1-(1-alpha)^(n+1)`. A first-sample initialized EMA produces impulse output `(1-alpha)^n` beginning at one and a unit-step response identically one. Both initialization conventions can be useful; only the former is the canonical zero-state response. The migrated API requires `initialization='zero'` or `'first'`, and tests both distinctly.

KAMA's old warmup directly copied the input but reported a pole computed from a slow coefficient. The new implementation uses the explicitly declared slow squared smoothing coefficient during warmup and returns its actual current alpha as state. This is a **changed algorithm definition**, not a claim of parity with the flawed warmup. The Architect must preregister which warmup variant is a canonical baseline and use common evaluation exclusions or sufficient prior history.

The exact EMA digital -3 dB crossing solves `cos(omega_c)=1-alpha^2/(2*(1-alpha))` when a crossing lies below Nyquist; a large alpha can have no such crossing. The small-alpha approximation `f_c≈alpha*fs/(2*pi)` is not exact. An adaptive trace has no single LTI transfer function; averaging alpha does not establish equal group delay, passband, noise gain, or detection fairness. The hardcoded legacy 0.08253 cannot serve as a portable fairness adjustment.

### 5.5 A presentation replay is not a streaming experiment

The old backend loads a historical slice, injects anomalies, creates synthetic bursts, computes all filter outputs in advance, loops the slice, shifts timestamps between loops, and sleeps at approximately 20 messages/s. The dashboard is an understandable classroom visualization, but its “live stream,” queue-utilization gauge, and anomaly feed have no direct relationship to measured detector decisions, worker service, or actual queue occupancy. Alpha is a coefficient; `1-alpha` is the first-order pole. Calling alpha an “Adaptive Pole” also blurs the quantity displayed.

A future UI can show signed evidence artifacts or actual runtime telemetry. It must separate source labels, model alerts, controller load, source time, ingress time, completion time, replay speed, and run identity. If the runtime drops a point, it must not show a held display value as newly processed evidence. A polished dashboard is a late usability deliverable, not a substitute for the runtime trace or study.

## 6. Mathematical foundation to preserve, prove, and qualify

### 6.1 Define the clocks and state before discussing frequency or delay

Use at least four named notions of time: provider/source event time, host monotonic ingress time, worker start/completion time, and an optional regular DSP sample-grid time. An event index is not elapsed seconds. Changing event rate, replay speed, admission mask, or batch size can change the relation between these clocks. All primary artifacts must include the relevant clock names and units.

The migrated event-domain operator is `y_n=alpha_n*x_n+(1-alpha_n)*y_(n-1)` on an admitted update. An `EMA` instance persists between batches. A first-sample initialization uses `x_0` as its initial state and marks that choice. A zero-state initialization treats the prior state as zero and applies the coefficient at the first sample. The adaptive coefficient target is `a*_n=a_max-(a_max-a_min)*L_n`; the controller moves its previous coefficient toward that target by at most a positive, explicit event-domain `max_delta` and retains the declared `[a_min,a_max]` bounds.

The current `EMAPipeline` updates the alpha controller at **every observed ingress event**, even if the EMA update is skipped. The EMA state changes only on admitted events, while its display output is held elsewhere. This corrects the legacy practice of computing the controller only on a compressed subsequence. It is one explicit design choice, not the only scientifically valid choice. If controller computation itself is skipped, or if slew is bounded per second rather than per event, implement/register a separate operator; do not alter clock semantics behind the same model identity.

The current engine has no full detector/runtime integrated into that pipeline. In the future runtime, a skipped event must have `processed=false`, no worker score or decision, and a preserved drop/skip status. Holding an output for presentation does not authorize evaluating a detector on every skipped raw input for free. A cheap ingress detector can be a separate policy, but its computation and alerts must be measured and labeled. No post-hoc inverse-probability correction is justified for deterministic load-dependent omissions unless the required assumptions are explicitly established.

### 6.2 First-order boundedness does not require a fabricated slew theorem

If `0<=alpha_n<=1`, the EMA update is a convex combination of input and previous output. For input bound `|x_n|<=M`, initialized bound `|y_-1|<=B`, induction gives `|y_n|<=max(M,B)` for every step. Holding state on skipped steps preserves the same bound. This is a direct first-order bounded-input/bounded-state argument; it does not depend on an arbitrary alpha slew bound or a frozen-pole plot.

For two states driven by the same input and same coefficients, the difference on an admitted update is `d_n=(1-alpha_n)*d_(n-1)`. Over admitted updates, `|d_m|=|d_initial|*product_j(1-alpha_j)`. If a positive lower bound `alpha_j>=a_min>0` holds, state differences contract at most `(1-a_min)^m` in **admitted-update count**. This does not promise a rate per physical second if no samples are admitted for a long wall-clock interval. With a bounded event-domain skip count, it gives an event-count contraction bound; a physical-time bound additionally requires bounded interarrival gaps. If the source itself is unbounded, no finite global output bound is implied.

For an exogenous fixed coefficient sequence and zero-state initialization, the time-varying impulse kernel is `h(n,k)=alpha_k*product_(j=k+1..n)(1-alpha_j)` for `n>=k`. This operator is linear in input conditional on that sequence, but not time invariant. If load and therefore coefficients depend on output, worker backlog, or task decisions, the combined closed loop can be nonlinear/endogenous. Do not invoke one frozen `H(z)` as the transfer function of that closed loop.

For a fixed coefficient `a`, the LTI transfer function is `H(z)=a/[1-(1-a)z^-1]`. For `0<a<1`, a −3 dB crossing in `[0,pi]` exists exactly when `a/(2*sqrt(1-a))<=1`, and its frequency is `w_c=2*asin(a/(2*sqrt(1-a)))` radians/sample. This equivalent sine form avoids cancellation in `acos(1-a²/[2(1-a)])` for tiny coefficients. For larger `a` there is no such crossing by Nyquist; returning an invented cutoff is incorrect. White-noise output variance gain is `a/(2-a)` for a zero-mean independent white input under steady-state LTI assumptions. Neither formula automatically describes the adaptive/admitted operator. Finite-precision behavior and representable-range failures need explicit checks; the proof above is real-arithmetic, not a guarantee of exact floating-point contraction at arbitrarily tiny `a`.

Slew control may reduce certain coefficient-induced transients or constrain controller changes, but “prevents ringing,” “ensures unconditional stability,” or “ensures quasi-static validity” requires the particular claimed bound and its conditions. A first-order EMA with nonnegative weights does not have the general oscillatory ringing phenomenon implied by some old prose. If a quasi-static approximation is important, derive a quantitative approximation-error bound and compare it with the implemented operator over allowed load histories, including abrupt changes. Numerical examples supplement a proof; they do not supply it.

### 6.3 Analyze the actual error caused by dropping updates

Let `v_n` be a full-rate reference using the same coefficient sequence and `u_n` the held/admitted approximation. Define `e_n=u_n-v_n`. If an event is admitted and both update with the same current input/coefficient, `e_n=(1-alpha_n)*e_(n-1)`. If it is skipped, `e_n=e_(n-1)+(v_(n-1)-v_n)`. Thus skipped reference increments accumulate and admitted updates contract prior error. A useful bound can be written as a sum of skipped `|v_j-v_(j-1)|` terms attenuated by subsequent admitted-step contractions. This identifies what actually controls distortion: reference variation, admission pattern, and subsequent coefficients.

The equality only applies when the reference and approximation share the declared coefficient sequence. In policy-specific endogenous queue control, different runs can induce different loads/coefficient histories; compare either a conditional common-load operator experiment or a full closed-loop policy effect, and name the estimand. Do not attribute closed-loop differences solely to the pole without controlling the admission and load paths.

For a special constant input across a skipped block, a block-equivalent coefficient is `a_eff=1-product_j(1-alpha_j)`. This can motivate an elapsed-gap update variant, but it is exact only under its stated input/holding assumptions. It does not reconstruct arbitrary skipped input samples, and a method that inspects all skipped prices to form the block update has incurred that inspection cost. Study compensated updates as a separately preregistered hypothesis if useful; do not insert them to improve the preferred method after testing.

Deterministic stride shedding also has aliasing and phase sensitivity. Use test-only impulses, alternating signals, ramps, and aligned/misaligned event positions to demonstrate the operator and detect edge cases. These mathematical fixtures are legitimate software/theory evidence, explicitly not empirical market observations. Test whether random or value-aware admission gives different risk, with randomness and any importance estimation fully declared.

### 6.4 Bandwidth and baseline matching must answer a specific question

For fixed EMA, DC delay `(1-alpha)/alpha` is in samples, and the exact cutoff relation appears above. Mean alpha equality is not equivalent to equal mean delay because the transformation is nonlinear; neither establishes equal output noise gain for an LTV sequence. Changing slew, input-rate distribution, or admission schedule further changes the operator. A comparison should separately report actual coefficient distribution, reference noise gain/fidelity, processing fraction, and relevant delay.

Maintain at least three fairness views: best-validation-config performance at equal total tuning budgets; mechanism-matched admission at comparable processing fractions/cost; and a declared smoothing-matched control based on a development-only criterion such as fixed-reference white-noise gain or measured response error. Do not promise every property can be matched simultaneously. For the white-noise criterion, use an explicitly mathematical calibration fixture and disclose that it defines a design property rather than measuring a financial signal's latent truth.

Uniform-grid Butterworth comparisons require exact digital cutoff design, SOS state, causal input mapping, and valid Nyquist constraints. The migrated wrapper checks design parameters and uses `scipy.signal.butter(...,fs=...,output='sos')`; its bare values API cannot verify a grid by itself. That obligation belongs to the future data adapter. Sparse event dropping cannot preserve a fixed Hz interpretation unless the operator handles irregular samples explicitly or a causal regular-grid transformation precedes it.

## 8. Research question, contribution, and falsification

The proposed primary question is: **Under a fixed resource and latency budget, does causal load-driven coefficient adaptation provide a useful quality/compute tradeoff beyond a well-tuned fixed filter with the same admission policy?** A secondary question is whether resource-aware admission itself yields predictable distortion/latency/loss behavior over realistic workloads. Define useful quality in the exact downstream application; without natural labels, evaluate approximation fidelity to a declared full-rate reference, not “accuracy at detecting real anomalies.”

Candidate contribution A is a mathematical characterization of admitted-update error and closed-loop assumptions, paired with a measured implementation. Candidate B is a rigorous comparison showing when simpler policies match or dominate adaptive ones. Candidate C is a reproducible benchmark/protocol disentangling filtering, admission, and task scores. Select a focused combination supported by results. Merely attaching backlog to an EMA coefficient and drawing frozen poles is unlikely to be a sufficiently established top-tier contribution without stronger analysis or systematic evidence.

The primary mechanistic comparison must be **adaptive EMA + admission versus fixed EMA + the same admission mechanism**, with additional controls for matched processing fraction and tuning budget. A claim about adaptation is falsified if its CI excludes a practically useful benefit or if fixed policies dominate it under the registered quality/latency conditions. A broad resource-saving claim is falsified if ingress/controller overhead cancels the claimed downstream savings, or if measured useful completions do not improve at acceptable loss/quality. A deployable-stability claim is falsified by sustained backlog growth, unacceptable tail delay/loss, controller oscillation, or failure to drain within the registered horizon.

Do not preregister that adaptation “will win.” Register an estimand, sign convention, meaningful margin, uncertainty target, workload population, and what evidence would refute it. If there is no defensible natural anomaly task, the correct paper is about approximate signal processing/runtime policy, with anomaly detection omitted or explicitly confined to a separate externally labeled or simulation study.

Butterworth on a valid grid is a classical DSP comparison, with sufficient design/shape explanation. RRCF or a modern streaming anomaly detector can be a task baseline only for a justified labeled task and with its full measured cost. Contemporary resource-aware/importance-aware shedding should be selected from verified primary literature and task feasibility, not from a name that guarantees the proposed method wins. If a strong method cannot be reproduced, record the failed reproduction and scope instead of silently excluding it.

Tune all relevant methods on development/validation with equal, reported evaluation/search budgets and registered hyperparameter domains. Register whether fairness means equal number of trials, equal total tuning time, equal compute, or multiple reported views. Record every attempted configuration, rejected parameter combination, runtime failure, selected config, and selection criterion. Do not tune only the preferred method aggressively while keeping competitors at weak defaults. Mean-alpha matching on test is prohibited.

### 13.2 Full factorial mechanism study

At minimum test a 2×2 factorial of **load-driven coefficient adaptation ON/OFF × load-driven admission ON/OFF**. Keep reference/data/scale/detector/task semantics aligned. Evaluate the main effect of admission, main effect of adaptation, and their interaction using explicit unit-level contrasts. Do not interpret `adaptive+shed` versus `fixed/no-shed` as the adaptation effect.

If slew limiting is a third claimed component, use all 2³ combinations where scientifically meaningful, with a valid no-slew operator. If detector/threshold adaptation is a fourth contribution, use all 16 combinations or remove it from the mechanism claim. The factory requires complete factorial for five or fewer components; for more, a fractional design needs a declared alias structure and loss of identifiability. Avoid multiplying components merely to inflate novelty. Match processing-fraction/tuning views separately when controllers produce different admission rates.

### 13.3 Workload axes

Prospectively define nominal/no-overload, near-capacity, sustained overload, observed source bursts, abrupt overload/recovery, and relevant source-rate heterogeneity. Accelerated replay is allowed as an explicit benchmark manipulation. Preserve actual realized host arrivals and missed scheduling deadlines; requested acceleration is not measured offered rate. Avoid random-source replacements and arbitrary source-row burst multipliers described as natural data.

Use common workloads and block randomization across policies. Source event traces can be common while policies induce different queue/service state; that is the closed-loop policy effect. A separate open-loop common-load experiment isolates coefficient behavior conditional on the same load. Report both when mechanism claims need both; never pretend an exogenous simulated trace is measured backlog.

Vary actual downstream operator costs, batch sizes, queue capacities, controller observation delay, missing/late events, signal/source rate, and initialization/reset policy where relevant. The primary axes must be bounded by a prospective compute/storage budget and minimum precision; do not run every possible combination and cherry-pick good regions.

### 13.4 Metric hierarchy and reference identity

Primary runtime outcome should count **useful completed work** under a specified latency/quality constraint, together with loss/admission fractions. Raw accepted input rate can be increased by discarding nearly everything; it is not useful throughput. Primary quality for unlabelled data may be fidelity to a specified full-rate operator/task output. That reference is a declared computational target, not an oracle of “true noise-free price.” If different filter families target different signal properties, report within-operator approximation plus a common downstream task view, rather than conflating adaptation with reference mismatch.

Report mean/RMSE and tail/worst error, held-output age, physical start/end/task-alert latency, overflow loss, admission fractions, resource readings, recovery/drain behavior, and subgroup worst cases. For labeled tasks report exact point AUROC/AP plus predeclared event recall/false-alert rates/latency with misses. Event tolerance, point adjustment, and any alert suppression must be named and preregistered. The rigorous-evaluation literature warns that point adjustment can substantially overstate anomaly performance; FlowGate's exact defect is established by its own code/probe, not merely by analogy to that literature. See [Kim et al., rigorous TSAD evaluation](https://arxiv.org/abs/2109.05257).

Pareto analysis uses matched evidence keys/config/data/workload/run blocks and actual paired estimates. Report uncertainty in both axes and dominance stability under paired resampling if claimed. A tied mean or overlapping intervals does not justify a special favorable status. “Nondominated among tested configurations under these conditions” is a scoped statement; it is not globally optimal or better than every competitor. Include dominated/preferred-policy failure regions.

## 14. Statistical design, precision, and conclusions that the data can support

### 14.1 Define the experimental unit before choosing a test

A million correlated trade ticks are not a million independent replications of a policy effect. A hundred injection seeds applied to one trading day are not a hundred independent days. Multiple assets observed during the same market shock may share a calendar-day dependence structure. Repeated timing runs on one host describe execution variability conditional on that host/workload, not generalization across hardware populations. The unit and target population must be specified for each outcome.

For market-data fidelity, one possible design is paired policy comparisons within each asset-day, with calendar day as the top-level resampling unit and asset as a repeated stratum. This is a candidate, not an already justified design: review autocorrelation across days, market regimes, and sampling scope. If a few contiguous days form one dependence block, use larger blocks and report the resulting smaller effective N. For a labeled benchmark, the independent unit may instead be the benchmark's device/run/series, not arbitrary windows cut from the same series. For execution, independent randomized blocks span separated host sessions/days as feasible; each block evaluates the same workload and policies under comparable host conditions.

The primary estimand must name population weighting. Equal weight per source unit, equal weight per asset, and event-weighted pooled performance are different questions. A busy BTC day must not silently dominate a supposedly equal-day effect. Retain both within-unit summaries and raw predictions/traces. If reporting a pooled descriptive metric, label it pooled and avoid using independent-point inference when events are serially dependent.

Use stable keys such as `(source_unit_id, workload_id, repeat_id, implementation_id, config_hash, epoch_id)`. A method comparison joins the common source/workload/repeat keys while asserting that task/reference/evaluation definitions agree. Reject duplicate keys, missing counterparts, changed input hashes, and differing horizons before calculating an effect. Never silently sort/truncate. Report missing/failing units by policy and reason. Complete-case analysis can itself be biased if a policy fails on its hardest workloads; register how failures enter the primary outcome rather than dropping them as inconvenient.

### 14.2 Pairing, dependence, and uncertainty

Pair policies on identical source/workload units. Aggregate injection/algorithm seeds within an independent source unit according to a registered rule, or use an explicitly hierarchical estimator that retains both levels. For source-day dependence, a paired block/hierarchical bootstrap must resample the independent top level and preserve paired policy rows and within-unit structure. The bootstrap algorithm, number of resamples, RNG seed, interval construction, and assumptions belong in the frozen analysis config. Its random seed ensures reproducibility; it does not create additional observations.

The current `paired_t_summary` is only a small, checked arithmetic implementation for an independent-unit paired mean under suitable assumptions. It does not establish those assumptions, supply a hierarchical bootstrap, prove robustness to heavy tails, or replace a power analysis. Use it where the methodology justifies it, or implement another prespecified estimator. Zero variance, unavailable metrics, numerical underflow, one-class subsets, and too few independent units must produce an explicit status and a limitation. Do not replace undefined p-values or intervals with favorable zeros/ones.

For AUROC, a classical paired DeLong calculation addresses aligned predictions under its sampling assumptions. It is not automatically appropriate for dependent ticks/injected blocks, and concatenating heterogenous runs changes the estimand. Prefer unit-level or dependence-aware paired uncertainty when the task/data require it. Validate any DeLong implementation against an independently specified example and an authoritative implementation/reference; a matching historical CSV is not a correctness oracle. Do not add DeLong simply because an earlier manuscript used it.

Latency summaries must preserve the joint fact of detection and delay. “Fast among 10% of events detected” is a different result from “fast at 95% event recall.” Report detection fraction, miss count, censored count, empirical delay distribution among detected events, and a registered deadline-success fraction over all eligible events. A restricted-time summary can be appropriate when defined prospectively; do not impute every miss as zero delay, omit it, or assign an arbitrary large number and call it measured latency. Right-edge windows need a registered eligibility/censoring rule independent of method outcomes.

Report confidence intervals and effect sizes with units alongside p-values. A bootstrap interval for a ratio needs a prespecified zero-denominator policy and a scientifically meaningful denominator. When baseline useful throughput is zero under severe overload, report raw differences and the failure state; an infinite percentage gain is not a useful headline. For multiplicative costs, state whether the estimator is ratio of means, mean of paired ratios, or log-ratio, because they need not agree.

### 14.3 Multiplicity, equivalence, and noninferiority

Register a small primary comparison family before confirmatory access. Specify outcomes, primary workloads/subgroups, baseline contrasts, direction, confidence level, and family correction. Use Holm where justified for a finite family; document the treatment of unavailable tests without deleting them after viewing results. Large exploratory sensitivity grids stay exploratory. Do not call every favorable uncorrected comparison a discovery while unfavorable comparisons disappear into an appendix.

Failure to reject a zero-effect null does not establish equal quality, safety, or “no degradation.” If preserving quality is central, use a defensible noninferiority margin in the outcome's natural units. Derive that margin from downstream task requirements or independent literature/domain judgment before confirmatory results; do not choose it to encompass observed damage. A one-sided CI must satisfy the registered boundary and confidence/multiplicity rule. Equivalence requires both meaningful bounds and the corresponding procedure; overlapping separate-method CIs are insufficient.

Do not use “significant improvement” for only a favorable point estimate or “statistically equivalent” for p>0.05. If the CI includes meaningful benefit and meaningful harm, the conclusion is insufficient precision. If it excludes a meaningful adaptive benefit while shedding itself helps, state that the tested adaptation adds no demonstrated practical benefit within the registered margin/population. A properly bounded negative finding can be more informative than a small positive p-value on a secondary metric.

### 14.4 Prospective budget and stopping rules

Run a development-only pilot to estimate runtime, variance, dependence, and measurement resolution. Record pilot data access and keep pilot observations out of the untouched confirmatory set unless a prospectively valid internal-pilot design is explicitly adopted. Choose the independent-unit count using a minimum effect or desired CI width tied to the claim, not “150 seeds” inherited from the old runner. Include attrition/failure scenarios and multiplicity in the design. Use conservative assumptions and disclose sensitivity to them.

Freeze either a fixed sample/run budget or a valid sequential procedure with predetermined boundaries and alpha spending. Do not stop when p first falls below a threshold, when the preferred method enters the Pareto frontier, or when the plot looks smooth. Additional test exposure following a failed study is a new/adapted study with its own provenance, not extra rows silently appended to the first.

No numerical claim of adequate power is made in this audit: there is no selected final estimand, margin, independent population, variance model, or runtime pilot yet. If the M3 budget cannot support the desired precision, narrow the claim or report the uncertainty. Storage/compute constraints do not justify fabricated replications or pseudo-independent windows.

## 15. Execution on the M3 MacBook Air: measure within the actual limits

The stated target is an ARM M3 MacBook Air with 8 CPU cores, 10 GPU cores, 16 GB unified memory and 512 GB storage. The audit environment record identifies the actual host/software observed during verification. The following are **proposed operating constraints**, not measured capacity, throughput, or memory results.

### 15.1 Environment and resource budget

Create a dedicated native arm64 environment. Do not reuse the legacy `.myenv`, resolve the NumPy/Numba incompatibility by downgrading arbitrarily without recording it, or run through Rosetta unknowingly. The migrated reference engine intentionally has no Numba dependency; NumPy/SciPy versions are recorded in its lock inputs. Produce a clean, resolver-verified environment with Python patch version, wheel/artifact hashes, architecture, optional dependency groups, and a repeatable installation command. A pinned text file without wheel hashes is not a fully attested environment. Verify source installation/import in a fresh environment before confirmatory runs.

If an optimized Numba/Cython/Rust/other backend is added later, it must be separate from the canonical reference, match state/skip/initialization semantics, and have differential tests across randomized valid inputs and adverse boundaries. Warmup/compilation time, generated code/cache identities, architecture, and cold-start behavior belong in results. “JIT is faster” is a hypothesis until measured. A compiled loop that omits the detector or allocation work is not an equivalent runtime comparison.

Use streaming/decompression batches and bounded columnar buffers; do not load all 73.8 million cached rows plus multiple float arrays/labels/masks into unified memory. The copied raw corpus is approximately 1.52 GB compressed. Parquet, raw traces, and many policy/repeat outputs can expand this substantially. Before acquisition/run, calculate projected source, intermediates, event traces, figures and backup sizes and check actual free space. A reasonable initial development envelope is one source unit at a time, bounded buffers, and a reserved memory/storage margin; the exact numbers must be selected after measured pilot RSS and disk growth, not written into evidence as though observed.

Retain one shared immutable input per workload and references/configs rather than multiplying identical data per policy. Chunk prediction/trace outputs with checksums and a manifest, preserving full lineage. Aggregates alone cannot support per-event audit, but per-event traces need not be copied into every summary. Set a disk threshold that stops a run cleanly with a retained incomplete receipt. Never silently truncate the tail or delete failed runs to regain space.

The GPU's existence does not accelerate the present Python/NumPy/SciPy streaming engine automatically. Add GPU claims only for an implemented GPU path with synchronization and host/device transfer costs measured, compatible task semantics, and equal relevant workloads. This study can be a CPU streaming paper; no GPU marketing number is needed. Do not infer memory bandwidth, power, or sustained speed from advertised core counts.

### 15.2 Timing, thermal state, and comparisons

The fanless Air can change performance during long workloads. Benchmark in randomized/interleaved blocks with a registered warmup, idle/cooldown rule, minimum measurement duration, host power/battery state, and background-activity record. Long calibration runs may themselves heat the machine; log order and elapsed-session time. Do not always benchmark the preferred method first on a cool system and slower baselines later. Record thermal/throttling information only where a documented measurement is available; otherwise report that it was not observed rather than inventing a temperature.

For short operations, batching reduces timer resolution noise, but preserves the operation's actual work and reports batch size and elapsed scope. Measure wall time with a monotonic high-resolution clock; measure process CPU time with a real process CPU clock when claimed; measure RSS with a documented host/process tool when claimed. Wall elapsed time is not CPU time. Peak RSS sampling can miss spikes; document sampling rate and scope. Factory placeholder CPU/memory fields must not become paper measurements.

Report cold start, warm steady state, ingress/controller-only, filter-only, detector/downstream-only, and end-to-end costs as separate named scopes where relevant. Primary runtime comparisons use the end-to-end scope including queue synchronization, admission decision, accepted/skipped bookkeeping, allocations, task work, and output delivery. Diagnostic decompositions explain overhead but do not substitute for total cost. The independent oracle may run offline outside the measured DUT if this is specified, with its own resource record; the DUT cannot use oracle labels or future signals to decide admission.

Use single-thread controls first to make capacity interpretable. Record BLAS/OpenMP/thread-pool limits and actual settings. A claimed multicore experiment must implement and report the concurrency scheme, ordering/state correctness, actual worker utilization, and aggregate process costs. Queue/controller state sharing changes performance and semantics; multiplying one measured core rate by eight is a model, not an eight-core measurement. Expose a baseline to the same concurrency resources.

Sleep prevention may be needed during explicitly started runs, but it is not thermal control. Remote/offline run scheduling, unattended permissions, and telemetry requiring privilege need concrete feasibility checks before freeze. If the required timing condition cannot be held, keep the failed/contaminated run and apply the registered rerun policy. Do not exclude “slow” repetitions solely because they disfavor the method.

### 15.3 Energy and portable claims

Energy is optional unless central to the claim. To claim it, use a documented instrument/tool that actually measures during the workload, integrate power over elapsed time at a sufficient sampling rate, state system versus process/package scope, record background/baseline handling, and report measurement uncertainty. Two readings before/after an operation do not supply its joules. If permission/tool limitations prevent credible measurement, remove the energy claim and emit `not_measured` with a reason.

Single-host results are valid conditional measurements if honestly scoped. Claims across CPUs, operating systems, deployments, or production exchanges need additional independent hardware/platform evidence. A second compatible host/architecture or independently reproduced artifact would strengthen portability, but do not fabricate that run or label an AI's arithmetic recomputation as a second physical machine. The final paper should identify precisely what was observed on the M3 and what is modeled or conjectured.

## 17. Claim-to-evidence matrix and mandatory rejection conditions

| Candidate statement | Minimum admissible evidence | What cannot establish it |
|---|---|---|
| First-order filter remains bounded | Correct recurrence, admissible alpha/state/input assumptions, proof and numerical checks | Frozen pole screenshot or arbitrary slew number alone |
| Approximation error is controlled | Defined common reference/clock, bound assumptions, measured per-event error including skips and boundary cases | Smooth-looking market plot or mean-alpha match |
| Adaptation improves useful overload operation | Matched-admission/factorial comparison, measured total runtime, task/quality and loss outcomes with paired uncertainty | Adaptive+shed versus fixed/no-shed only |
| Sustainable throughput increases | Real completion/queue traces, offered/admitted/dropped accounting, registered sustained backlog/latency criteria | Inverted filter microbenchmark, doubly divided shedding formula, GPU/core-count extrapolation |
| Quality is preserved | Valid task/reference and prospective noninferiority margin/CI with appropriate dependence handling | p>0.05, overlapping separate CIs, detected-only samples |
| Anomalies are detected | Authentic task labels or explicitly artificial injection task, causal scores, exact/event-defined metrics, complete misses/alerts | Unlabeled prices, injected labels wired into UI alerts, point-adjusted numerator with strict denominator |
| Energy decreases | During-run integrated measurement with scope/uncertainty and common task completion criteria | Before/after power samples, missing power column, faster code alone |
| Results generalize | Prospective independent population/OOD evidence and explicit hardware/task scope | Repeating one day under many seeds or one host under new names |
| New research contribution | Primary-source comparison, precise gap and evidence addressing it | Old prose declaring novelty, absent citations, weak default-only baselines |
| Submission artifact is reproducible | Fresh clone, lawful inputs, compatible locks, frozen source/config/trace lineage and recomputation | Passing engine tests or a certificate from an inapplicable binary profile |

Reject an empirical run if its source identity is missing/changed, source acquisition falls back, labels are unexplained, outputs contain impossible time/accounting states, fitted transforms leak test/future information, results are copied from quarantine, or key implementation/config/dependency identity is absent. Reject the specific unsupported claim rather than pretending every exploratory artifact is useless. A deliberately simulated FCFS trace can support a model check when honestly labeled; it cannot support observed system latency. An explicit unit-test input can prove an operator property; it cannot count as a market trial.

Hardcoded constants require a reason and role, not a blanket keyword ban. Mathematical coefficients, a documented protocol default, an independently motivated threshold, deterministic test fixtures and a preregistered workload parameter can be legitimate. Data-derived constants require a training/development provenance record and separation from confirmatory access. A value chosen to bias a preferred method or a fabricated measured value is prohibited even when disguised in a config file. Behavioral/data lineage tests matter more than scanning for words such as `random`, `simulate`, or `synthetic`.

## 25. Mathematical contract refinements for C01, C03, C05, C07 and C10

### 25.1 Commanded coefficient, effective recurrence, clocks, and startup

For a zero-state EMA or an ordinary update after explicit startup, the held/admitted recurrence is `y_n=(1-beta_n)y_(n-1)+beta_n*x_n` with `beta_n=k_n*alpha_n`. For first-value initialization the first admitted observation assigns the state, so its effective beta is **one**, irrespective of the command. A hold has effective beta **zero**. `FilterObservation.alpha` records the commanded coefficient, `initialized_from_first` records the assignment and `effective_beta` records this distinction. A trace adapter must preserve all three; neither startup nor a hold is an ordinary alpha update.

The event clock, admitted-update clock and physical elapsed-time clock are different. The current controller advances on ingress; the EMA advances on admitted observations; KAMA’s window counts the observations it actually receives. No missing events are implicitly inserted or recovered. Declare reset/carry behavior at batch, file, day, asset and session boundaries. If batch calls fail, the new numerical APIs restore their pre-call state; the runtime must still retain the failed attempt and its externally observed prefix/failure status. A numerical rollback does not erase already emitted sink effects in a future physical runtime; that requires a separate trace/accounting contract.

Convexity establishes ideal-real-arithmetic boundedness for bounded input and an explicitly finite initial state. Conditional forgetting is the product of `1-beta`; infinitely many holds without admitted updates do not guarantee forgetting. A proof on a common declared coefficient/mask path is not a global contraction proof when two feedback trajectories generate different paths. Bound the feedback policy itself before stronger closed-loop claims. All finite-precision/error-range assumptions remain explicit; neither a positive nominal alpha nor a plotted frozen pole guarantees a numerically resolved physical response for extreme values.

Frozen EMA DC delay and cutoff describe a fixed operator on its regular update clock. The stable cutoff expression is `2*asin(alpha/[2*sqrt(1-alpha)])` when a crossing exists; the implemented boundary classification uses the exact rational value of the supplied floating-point alpha. No crossing exists above the nominal threshold `2*(sqrt(2)-1)`. These diagnostics do not attach Hz or a unique transfer function to the full adaptive/admitted system. For a uniform-grid Butterworth baseline, register the raw-to-grid transformation, interpolation/aggregation, empty bins, grid origin and time window; never feed irregular trades into a nominal uniform-Hz filter and call the comparison matched.

Elapsed-time smoothing is a distinct operator requiring a reconstruction model, not an automatic patch. A time constant may imply `alpha(dt)=-expm1(-dt/tau)` under the stated hold/update convention, but the convention determines which observation drives each interval. Register zero-time multiple trades, long gaps, startup/reset and the task’s desired units. This must remain separately named from the event-domain operator so apparent advantages are not produced by silently changing clocks.

Their expected behavior is honest accounting or a retained failure, not necessarily a favorable score. The worker’s total-system cost includes ingress/control/queue/compute/detector/serialization/sink overhead; no alpha-specific operation-count saving is inferred from a scalar coefficient change.
