## Implemented changes and their limits

The audit now verifies signatures on retained completed execution attempts and binds run nonce, project, epoch, experiment, seed, frozen input aggregate, lock hash, declared launch, output aggregate, exit status and times. Merely rehashing a changed output file no longer restores an admissible receipt. Attempt directories must form a contiguous numbered sequence. This detects missing interior slots; it is **not an externally anchored append-only attempt ledger**, and cannot prove that a same-user actor never removed a final attempt or an entire epoch. The domain adapter still needs the planned attempt ledger and deletion mutations.

Typed launches and audit recomputation use the same resolver. The existing isolated standard-library runtime uses `-I/-P/-B/-S` where supported; it does not currently expose a NumPy/SciPy research environment. A dependency lock file’s hash does not establish that the installed packages match it. Legacy commands remain compatible, but their actual launch runtime is marked `legacy-command-unattested`; their supervisor Python observation is not mislabeled as the worker interpreter. For requested `network=disabled`, the local runner refuses to launch because it does not implement network isolation. Requested OS resource-limit setup errors are retained as failed launches rather than silently ignored. OS address-space/process limits are not measurements of unified memory, RSS or application latency.

CPU time and peak memory in signed receipts are **null when unmeasured**. Wall-clock duration retains its separate name. They are never replaced with wall time or zero. The next runtime must supply measured, scoped resource telemetry, overhead measurements and unavailable-status reasons if those quantities support claims.

Ed25519 uses `cryptography`. HMAC fallback is local-only and exports a key fingerprint rather than a signing secret. A legacy HMAC public file containing its secret is refused; rotation requires an explicit new-key/new-epoch action preserving old evidence. Algorithms cannot silently downgrade, receipt verification does not create missing keys, and incomplete key material is not overwritten automatically. Public bundle verification requires Ed25519. These same-user Python processes do not isolate signing material from a hostile worker; verified local signatures do not mean sealed evaluation. A reviewer supplied with a public key must also establish its identity independently of a self-asserted bundle.

Local assurance is at most `SUPERVISOR_ATTESTED`, after every computed run has verified receipt bindings. A result path is insufficient. A review declaration does not promote the level to sealed evaluation or independent review. `READY_FOR_HUMAN_SUBMISSION_REVIEW` is a lifecycle status with a separate limited assurance field. It does not assert scientific validity, novelty, hostile-worker safety or journal readiness.

The separate offline verifier reads the actual nested supervisor receipt, verifies its signature when an independently supplied public key is available, and compares signed output membership/digests against the archive. It rejects malformed JSON/paths and does not treat HMAC fingerprints as public verification keys. Without a public key it checks bytes/membership only; an archive’s claimed assurance is reported separately from achieved verification. It does not rerun scientific evaluation or establish source authenticity, population validity, installed dependencies or label independence.

The paired sign-flip statistic is compared in normalized units with a disclosed floating-point tolerance of eight ulps. The old absolute tolerance changed p values under unit scaling. Exact enumeration remains used for at most 16 paired units; larger cases retain the disclosed seeded Monte Carlo plus-one test. These numerical choices are not empirical results. The null needs joint invariance of paired differences under independent sign changes; mean zero or a small p value alone does not establish that assumption. Seed repetitions over a fixed test corpus remain conditional evidence, not independent market days. Floating-point variance underflow is refused rather than called true zero variance. Designs with an unattainable exact-test significance threshold are refused before execution; this is arithmetic feasibility, not a power or independence proof.

There is no universal 0.5 chance baseline for F1, precision, recall or raw accuracy. No unit-dependent minimum CI width is imposed. Negative/null outcomes are retained; exact-zero p values and zero-width intervals become review diagnostics. Nonfinite/out-of-range p values and reversed intervals are invalid and cannot be waived by an investigation note. An explicitly unresolved investigation fails. Flat sensitivity is a valid observed grid diagnostic; arbitrary 0.005/1% outcome thresholds no longer force a nonflat result.

Standalone deterministic applicability binds actual method-evidence bytes and a substantive rationale and reports training as `NOT_APPLICABLE`. It refuses fictitious epochs. Learned-method standalone validation requires an explicit budget/stopping rule and hashed contiguous loss history; there is no universal ten-epoch convergence rule. A completed budget is not proof of learning or convergence. The binary lifecycle retains its own declared training contracts; it is not a general DSP certificate. Failure taxonomy does not require three invented categories: one actual category or explicitly accounted no observed failures is allowed.

Bytecode under `__pycache__` is no longer silently omitted from frozen input checks. Tests use isolated temporary signing keys. Prepare clean source inputs before freeze; do not weaken inventory rules to admit opaque executable cache bytes. The compatibility field named `snapshot_merkle_root` is a sorted path/digest aggregate, not a Merkle tree with inclusion proofs. Changing its serialization requires a future epoch/version, not a retroactive alteration of receipts.

Coverage checking now identifies the actual engine modules and reproduction-identity helper. It remains a static reachability approximation, not proof of scientific enforcement. The attack registry validates its own structure; release audit does not automatically execute all its fixtures. Test execution is recorded separately. In particular, the phantom-ID fixture does not prove detection of hidden copying of correctly identified held-out labels. Register additional domain mutations and inspect the actual paths they exercise.
